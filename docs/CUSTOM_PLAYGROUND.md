# 定制游乐场

## 普通对话

选择分组，并分别预选对话模型和生图模型。输入明确的绘图要求（例如“画一张海边小屋”）时使用生图模型，其他消息使用对话模型。意图识别在浏览器内根据文字与上一轮类型判断，不额外调用付费分类模型；“写一个生图提示词”“解释这张图片”等请求仍作为文字对话处理。

生成图片期间可以继续输入并提交下一次请求。图片与各自的请求关联；更换模型不会改变已提交请求的模型。视频模型不显示在聊天或图片模型列表中，Seedance 仍使用官方原生视频任务接口，参见 [Seedance API](seedance-api.md)。

## 流程对话

切换到“流程”后，可以提前配置多条提示词，并沿用预选的聊天和生图模型。每一步成功后，用户决定是否点击“下一步”；下一步使用之前的成功结果作为上下文。对结果不满意时，可以填写修改指导并重新生成，再将最新成功结果传给后续步骤。

流程与普通聊天分别展示历史记录。流程草稿在首次运行前自动保存，保存失败时不会发起付费请求。提示词和文字结果保存在当前账号下，可以跨设备继续使用。图片缓存在当前浏览器，刷新后重新打开会话可恢复未过期的图片；换设备或图片过期后，需要重新生成依赖的图片。

## 保存与计费

- 普通聊天和流程共享每个账号最多 30 条云端记录的限制，每条记录自创建起保存 7 天，继续对话不会延长到期时间。
- 图片自动缓存在浏览器中，自生成起保留 10 分钟，刷新不会延长期限，支持下载。浏览器禁止或无法写入缓存时页面会提示，图片仍可在当前页面查看。图片不写入服务器聊天记录。
- 普通对话和流程支持手动选择 1–10 张图片，也可通过“画三张图片”等明确指令指定数量；超过上限或无效数量会被拒绝。
- 当前浏览器按账号记住上次使用的分组、聊天模型和生图模型；模型不再可用时自动选择可用模型。
- 所有生成请求继续经过已有的 Playground 分组 API Key、余额检查、分组内容审查和用量计费链路，管理员通过现有用量和审计页面查看记录。
- 使用余额付费的 Playground 生图，在访问上游前按请求张数和分组图片倍率原子冻结预计费用。并发请求共享数据库中的可用余额，余额不足返回 402；成功后按提交时的单张价格与实际返回张数结算，并释放差额。审核拒绝不会冻结费用。
- 未登录时，IP 加端口访问会先跳转登录；登录后返回游乐场。HTTP 页面中的会话 ID 生成不依赖仅限安全上下文的 `crypto.randomUUID()`。

迁移 `240_playground_image_balance_holds.sql` 保存生图冻结记录。上游成功但本地结算失败，或服务在请求期间中断时，尚未结算的冻结记录保留为 `pending`，需要管理员核对上游结果后结算或退款，不能直接清除冻结余额。这项保护只覆盖 Playground 余额生图请求；其他 API 请求和订阅额度继续使用原有计费规则。

## 验证

`tools/verify-community.sh` 检查定制 API、模型/意图选择、HTTP ID 兼容性、聊天与流程交互、历史记录隔离及计费回归。生产构建使用项目固定的 pnpm 9。发布后必须等待相同提交的 CI、安全扫描及定制镜像构建成功；生产激活与重启由管理员决定。

设置 `PLAYGROUND_HISTORY_REDIS_ADDR` 可以运行真实 Redis 历史保存回归；设置指向测试 PostgreSQL 的 `PLAYGROUND_BILLING_POSTGRES_DSN`（URL 格式）可以运行 `TestPlaygroundImageBalanceWithPostgres`，测试会创建并清理独立 schema，验证并发准入、部分结算和退款竞争。
