# 任务花园

花朵固定在登录后的侧栏。悬停可以看到接下来做什么，点击可以查看三项日常任务、一个周挑战和已经拿到的奖励。用户在 API 或游乐场正常创作，两处的有效产出共用同一份进度。

## 玩法与节奏

| 周期 | 任务 | 玩法 | 默认奖励占本周预算 |
| --- | --- | --- | --- |
| 每日 | 简单 | 签到或小目标，先拿到一次完成反馈 | 1% |
| 每日 | 中等 | 根据近期习惯完成有效请求、文字输出或图片作品 | 3% |
| 每日 | 困难 | 同样按实际创作，目标量更高 | 6% |
| 每周 | 周挑战 | 累计本周的产出，部分方案要求多个不同的创作日 | 30% |

每天三个任务共享成长展示。完成第一项后种子发芽，三项全部完成时开花。周挑战独立结算，领取后累计一朵收藏花。累计 1、3、6、12 朵依次解锁外观徽章。周一翻篇时用户保留收藏，可以从新一周继续。用户领取前就能看到目标和奖励。

## 生成与结算

1. 使用站点时区，以周一零点为自然周起点。四档各有 50 个参数化方案，账户和档位决定序列起点，周期每次推进 17 位。17 与 50 互质，同一档走完 50 个周期才会回到同一方案编号。
2. 每个用户在本周第一次访问时，服务器一次性保存七天的日任务和一个周挑战。日目标参考首访前本周已结束自然日的产出，周一以上周为基准，周目标参考上周产出。文字、生图、混合和新用户使用对应的指标与起步门槛。上周和本周已结束的日期均无使用记录时，首访当天的简单任务为签到。页面只展示当天三项和当周挑战，进度计入对应自然日或周内已完成的产出。下个自然周由用户首次访问触发新计划。
3. 有效请求至少有一个输出 token 或一张产出图片。只有输入、页面切换、复制文本均无法推进产出任务。签到由服务端在领取时记录。使用同一笔产出可以同时推进匹配的日常任务和周挑战。
4. 本周奖励池 `B` 以上周可核实的实际钱包消费乘 10% 为上限。上周零请求时使用 10 站内美元。有请求且钱包消费为零时预算为零，完成任务仍可参与成长和收藏。订阅消耗与上游账号成本分别核算。
5. 数据库以百万分之一站内美元为奖励单位，每笔向下取整。七天日任务共分配 70%，周挑战分配 30%。领取时检查归属、进度和过期时间。数据库在钱包入账时另行执行每人每周 `B + floor(B / 10)` 的硬上限，公式中的 `B` 使用整数微美元。配给 10 美元时，正常任务合计最多 10 美元。累计恰好 11 美元可以入账并触发管理员告警，尝试超过 11 美元会整笔拒绝并触发管理员告警。

升级过渡期间，旧版普通请求可能只有费用估值，历史记录仍计入请求数与产出。只有能核对的钱包扣款才计入预算，因此首周老用户的预算可能偏低或为零。新结算记录会保存实际钱包扣款金额，后续完整自然周可以据此计算。

例如，上周钱包实际使用 80 站内美元，本周预算为 8。默认每天三档各可领 0.08、0.24 和 0.48，周挑战另可领 2.40。七天全勤完成所有任务，合计正好 8。上周零请求时对应为每天 0.10、0.30、0.60，周挑战 3.00。

## 服务架构

| 层 | 职责 |
| --- | --- |
| 侧栏和任务框 | 显示服务器快照，开花、领取反馈、收藏徽章和重置时间 |
| 用户接口 | `GET /api/v1/bloom/tasks`、`POST /api/v1/bloom/tasks/:id/claim`，使用已登录账号身份和面板限流 |
| 规则引擎 | 根据账号、站点日历、历史产出生成模板、阈值、奖励和进度 |
| PostgreSQL | 保存账号周预算、不可变的任务快照和逐笔奖励流水。相同任务的并发领取通过行锁和唯一约束只入账一次 |
| 余额缓存 | 事务提交后失效该账号的钱包缓存及 API Key 鉴权缓存 |
| 管理员告警 | 达到和超过硬上限的事件记入「运维监控 → 告警事件」，按用户、周和事件类型去重。已配置 SMTP 和运维告警收件人时，提交后立即按运维邮件设置投递。 |

## 管理员奖励策划

在「系统设置 → 用户」选择管理员自己持有的站内模型 Key 和模型后，可生成四种使用画像的日奖励比例。每次主动生成发起一次模型调用，按所选 Key 计费。模型收到四种匿名画像定义，系统保存 Key ID、模型名和校验通过的分配表。

每日三个比例之和固定为 10，周挑战固定为 30。简单奖励占 1% 至 2%，中等与困难依次增加。普通用户的任务接口只返回任务、进度和奖励。用户首访发任务时，服务器验证管理员配置的 Key，失效时按默认的 1%、3%、6% 分配。已发出的整周任务沿用首访时的配置与额度。
